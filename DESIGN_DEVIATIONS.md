# Design deviations

Per `design/CLAUDE_CODE_PROMPT.md` rule 2.1: the design files are the specification, not inspiration.
Anything that seems like it should differ from the design goes here — ask before changing it, never change it unilaterally.

| Page | What the design shows | What I think it should be instead | Why | Status |
|---|---|---|---|---|
| `college/batches.html` | Just "Build a batch" (course+semester select, from already-enrolled students) + "Your batches" grid + an "Undo most recent batch" card | Keep the real, connected "Request a new batch" workflow (lets a college request a batch for students not yet enrolled, pending company approval — has its own approval page on the super-admin side at `/lms/company/trainers/batches/requests`) alongside the design's simpler flow, rather than deleting it | This is real, working, cross-portal functionality, not a cosmetic add — removing it unilaterally felt riskier than asking. The page currently shows both the design's "Build a batch" flow and this extra one | Asked — not yet changed |
| `college/content-requests.html` | Each pending request shows the student's attendance % and a free-text reason they gave for requesting the content | `ContentAccessRequest` has no `reason` field at all — students don't currently write one when requesting. Showing attendance % would also need an extra query per request. Flagging as a real schema gap rather than fabricating text | Asked — not yet changed |
| `student/content.html` | One page per student: a course `<select>`, then one `<details>` per **module** showing its items inline when unlocked, or a single state (Locked / Available to request / Request sent) for the whole module | The real app currently grants and gates access per **item** (`ContentAccessRequest` keyed by `courseContentId` or `courseModuleId`), via a 3-level drill-down (courses → modules → items), each item individually requestable | Collapsing to the design's per-module granularity would be a real behavior change (trainers/admins currently approve individual items, not whole modules) — this is a data-model-level difference, not just layout, so I didn't restructure it without asking | Asked — not yet changed |
